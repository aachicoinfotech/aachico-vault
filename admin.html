# Aachico Vault Secure v2 ## Files - `Aachico_Vault_Secure_v2.html` — repaired frontend - `firestore.rules` — company/admin Firestore protection - `storage.rules` — protected vehicle document uploads ## IMPORTANT: Firebase setup The old screen accepted any non-empty password. v2 uses Firebase Authentication. For each company, create an Email/Password Firebase Auth user with this email format: `companycode@admin.aachico.com` Example company code `RJ27-FLEET` => email `rj27-fleet@admin.aachico.com`. Then create this Firestore document: `companies/RJ27-FLEET/admins/` with: `{ active: true, role: "admin" }` Also enable: 1. Firebase Authentication -> Sign-in method -> Email/Password 2. Firebase Storage 3. Publish `firestore.rules` 4. Publish `storage.rules` Do NOT put a service-account/private key in this HTML. ## What was repaired - real Firebase Auth login - company/admin authorization check - protected Firestore access rules - protected Storage uploads - permanent PDF/image document URLs - 10 MB upload limit and MIME validation - driver PIN is stored as SHA-256 hash instead of plain PIN - removed fake invoice defaults for rate/toll/parking/advance - invoice GST uses saved master GST rate - corrected invoice grand total - improved P&L expense fallback - corrected Udhari due calculation - safer HTML rendering for user data - safer CSV quoting - batch-based master reset - vehicle-document delete support - session logout signs out Firebase Auth ## Note The Firebase config values in frontend code are not themselves secrets. The actual security boundary is Firebase Authentication + Firestore/Storage Rules.
